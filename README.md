# 悦山公寓运营系统

一个面向小型公寓的 Django Web 应用。首页以房态为中心，记账、人员和合同均有独立入口，管理房态、人员、合同、收支和导出报表；Excel 只作为初始化导入和对外导出，不再作为主数据源。

## 日常操作与查询优化（2026-10-06）

- 从房间进入“记一笔”，优先显示该房间未结事项，点击原事项即可带入租客、费用期间和余额；“新增其他收支”保留公共、房间及指定合同的录入。按收/付过滤适用款项，退押金通过所选当前合同的退租结算办理。
- 入住表单折叠紧急联系人、中介佣金、优惠和特殊约定；半年/一年按钮按合同开始日计算包含首尾的租期，仍可手工修改日期。
- 新增人员可“保存并继续添加”：保留房间、入住类型和返回位置，清空上一人的身份信息；暂住未知日期不自动填今天。复用人员搜索显示当前在住房间。
- 收租增加已建账未收、尚待核实登记、已交齐筛选，默认待处理优先。已确认未收与待登记参考金额分别统计，筛选和分页不会把总额缩成当前可见部分；粘贴房号可带出跨筛选的房间。收款后保留状态筛选。
- 收支记录默认本月，可点击“查看全部月份”；流水、房间详情和人员详情的账务记录每页 50 条，最新记录优先，收支合计覆盖整个筛选范围。
- 房态、合同余额和收支合计采用批量查询或数据库汇总；现金核销与押金抵扣分别汇总，保留续租链、历史欠款和换房后的归属。
- `0013_billing_checkpoint` 仅新增检查点表，不生成账单或改变旧数据。网页按日、计费截止日期和账务变更检查是否需要补跑，仍保留首次访问补跑。修改合同、费用规则、账单、流水、核销或押金抵扣会使检查点失效；生成失败会回滚，下一次重新尝试。已生成的手工金额和作废账单保持不变。
- 可选每日定时执行 `python manage.py refresh_operations`；`--through YYYY-MM-DD` 指定截止日，`--force` 强制重新核对。没有配置操作系统定时任务也可使用网页补跑。维护脚本若直接使用 `QuerySet.update()`、`bulk_create()` 或原生 SQL 改账务，应在结束后执行 `refresh_operations --force`，这些接口不会触发模型保存信号。

## 记账工作台（2026-10-05）

记账统一为“收租、待收待付、收支记录”，各页只提供一个“记一笔”录入入口。房态上的记账按钮也进入同一表单。

- 新事项选择收钱/付钱、款项、金额和已收付/未收付/部分收付。公共维修、工资可不选房间；房间费用可不关联租客。租金、押金、取暖必须指定合同，支持历史租客。
- 已登记待办直接选择原事项，或在待办行全额收付、展开分笔金额和实际日期，避免重复建立账单。重复提交同一表单不会重复记账。
- 收租页保留按房号批量、单户部分收款；可选择合并本月已经登记的取暖费。押金在同一收租模块切换“合同押金”。待登记金额不代表已确认欠款。
- “预收租金（余款预存）”用于提前交租：只抵同一租客合同链的欠款，余款保存为预存。普通维修、赔偿等明确款项只结算本次事项。
- 退租同页记录损坏扣款、押金抵欠、应退金额和是否当天已退款。抵欠不是新的现金收款；未退款保留待付。扣款需说明原因，扣抵及退款不得超过实持押金。已用于结算的原押金收款不能直接减少或撤销。
- 新合同保存自己的水、电、取暖、物业、网费、停车标准；续租可填写新标准，默认沿用旧约定。修改房间默认费用不影响已有合同。已生成应收金额仍为快照。
- 房间详情显示各份合同和扣抵记录；收支记录按实际日期列流水，账单按费用期间查看。月度已结金额可能包含押金抵扣，现金进出以收支记录为准。

迁移 `0012_accounting_workbench` 增加合同费用约定与防重复标记。既有合同按升级时房间标准保存基线，不推断过去每份合同的真实旧标准；不创建收款、押金或历史账单，不启用自动计费。合同中途分段调价仍需明确处理对应账期，续租调价使用新合同。

## 快速启动

Windows 调试时，双击 `启动公寓.cmd`，或运行 `./run_local.ps1`。启动器自动启用名为 `utils` 的 conda 环境，先检查再升级数据结构，不会每次启动都重新安装依赖；不需要预先执行 `conda activate` 或配置 PowerShell profile。`./run_local.ps1 -DryRun` 只检查环境，不迁移或启动服务。

首次安装可执行：

```powershell
conda create -n utils python=3.12 -y  # 已有 utils 时跳过
conda run -n utils python -m pip install -r requirements.txt
conda run --no-capture-output -n utils python manage.py account owner  # 无账号文件时创建
.\run_local.ps1
```

电脑浏览器打开 `http://127.0.0.1:8000/`。手机和电脑在同一内网时，用电脑内网 IP 加端口访问。

Windows 入口使用 `DEBUG=1`、HTTP 和 Django 自动重载，修改代码后自动生效；R4S 使用独立的 Docker / Gunicorn 入口与 HTTPS 配置。端口被占用时运行 `./run_local.ps1 -Port 8001`；仅本机调试可加 `-BindAddress 127.0.0.1`，调试器需要单进程时可加 `-NoReload`。双击入口也支持传入这些参数。Conda 位于自定义目录且未加入 PATH 时，设置 `CONDA_EXE` 为 `conda.exe` 的完整路径。

当前本地已配置 `18611133192`、`18518912031` 两个普通业务账号，使用各自指定密码登录。实际凭据只保存在被 Git 和 Docker 构建排除的 `config/accounts.json`，不会随代码提交或进入镜像。部署时需单独迁移该文件，见 R4S 部署说明。

已有安装更新后需先安装新增依赖；仅在没有账号文件时用 `conda run --no-capture-output -n utils python manage.py account owner` 创建首次登录账号。账号由 `config/accounts.json` 管理，密码交互输入，文件只保存哈希，不提供默认密码。登录后才可访问业务页面、修改接口、上传图片和导出报表；退出使用页面上的“退出”按钮。

### R4S / iStoreOS 长期运行

已提供 Linux ARM64 Docker 镜像、Gunicorn、中文字体、持久化 SQLite/上传目录，以及使用免费 DuckDNS + DNS 验证证书的 HTTPS 网关配置。详细步骤与账号管理见 [R4S 部署说明](deploy/r4s/README.md)。仓库不包含实际账号、证书或部署密钥，准备代码不等于已部署。

日常账号管理：

```powershell
conda run --no-capture-output -n utils python manage.py account owner            # 创建 / 重设密码 / 重新启用
conda run --no-capture-output -n utils python manage.py account owner --disable  # 禁用，已有会话下次请求失效
conda run -n utils python manage.py check_runtime            # 只读检查
conda run -n utils python manage.py backup_database           # 在线一致性数据库备份
```

新增普通账号使用相同命令替换用户名；所有普通账号目前拥有相同业务维护权限。可在账号文件中删除账号或设置 `is_active=false`，无需重启；修改密码会使旧会话失效。`--admin` 额外允许进入 Django 管理后台，R4S 公网网关默认不转发该后台。账号文件是唯一凭据来源，`createsuperuser` 和后台用户表不负责配置登录账号。

### 项目位于 WebDAV / RaiDrive 时

SQLite 数据库不适合直接放在 WebDAV、RaiDrive、NAS 等远程挂载盘上，可能出现 `database is locked`。代码可以继续放在远程盘，但建议把数据库文件放在电脑本地，例如：

```powershell
$env:APARTMENT_DB_PATH="$env:LOCALAPPDATA\YueshanApartment\db.sqlite3"
New-Item -ItemType Directory -Force (Split-Path $env:APARTMENT_DB_PATH) | Out-Null
python manage.py migrate
python manage.py runserver
```

如果远程盘中的 `db.sqlite3` 已经有正式数据，请先停止程序，再把它复制到上述本地路径，然后运行。不要在程序运行期间复制 SQLite 数据库。

## 从零开始

新公寓不需要先做 Excel。进入网页后可以直接：

- 在 `房间` 页面新增房间，维护房号、挂牌价、佣金基数、密码、固定费用等信息。
- 房间卡片直接办理入住、收款、登记人员、续租、退租和换房，详情页维护二维码和完整资料。
- 在 `人员` 页面新增或修改人员；新增人员时直接选择房间和入住类型。
- 在 `记账` 中记录收款、支出或增加待收待付，补充临时费用。

## 导入模板

在 `更多` 点击 `下载模板` 会得到三张核心表：

- `房间与合同`：一行一间房，可同时填当前主租客和合同。
- `入住人员`：一人一行，用房间号关联，适合多人同住、暂住、管理员。
- `期初账务`：一行一笔接管当天的待收待付或已收已付。

填好后在 `更多` 点击 `导入表格` 上传。历史旧账和旧合同建议不迁入系统，只录当前真实状态和从今天开始需要管理的信息。

如需清空业务数据重新开始：

```powershell
python manage.py clear_business_data --yes
```

## 日常入口

- `房态`：默认首页。搜索房号、姓名或电话，筛选空房、到期未收和即将到期房。空房直接办理入住，在住房直接收款，卡片“操作”可登记人员、续租、换房和退租。
- `按月收租`：从首页或记账页进入，选择房租月份，勾选房间或粘贴已交租房号，核对户数和未结金额后一次确认。未收为红色，已交齐为黑色；每户自动生成独立流水，可在全部账单中修改或撤销。部分交租在对应行填写“本次实收”并点击“记录收款”，以后批量只补记余额。已有预收款先抵扣，已交齐的房间跳过，重复提交不重复记账。
- `批量登记押金`：从房态、记账或按月收租页进入，只对勾选的当前合同登记实际收到的押金。未建押金账单时预填每户 3500 元（合同有明确金额时沿用，可逐户修改）；已有账单沿用原金额。扣除已收押金，逐户生成独立流水，已收齐的房间跳过，重复批量提交不重复记账。部分收款填写“本次实收”并点击“记录本笔押金”，也可继续使用单独收款中的“指定押金”。仅补建押金账单，不启用自动计费或生成房租、取暖账单。收款可在押金账单或收支记录中修改、撤销。
- `记账`：分为待收、待付、收支记录。待收包含押金和临时费用，房租与取暖费按月合并；待付包含手工费用。“更多筛选”保留房租取暖和固定待付筛选。
- `收款`：填写房间和实际金额，先预览抵扣，再保存。默认租金优先，其次押金、取暖费等，多收的钱作为预存。指定押金或补交旧合同欠款时展开可选项。
- `记支出`：记录实际支出，不自动抵扣其他待付款。支付已登记的待付账单，请在该账单上确认付款。
- `增加待收 / 待付`：只登记尚未实际收付的钱。已生成账单可就地调整，刷新不会覆盖人工金额；作废自动账单后不会重新生成。
- `人员`：默认当前在住，可按房间、姓名、电话或身份证查找，登记离开后保留历史。可直接登记探望/暂住，日期未知可留空；到期只提醒，不自动移出在住名单。同一人员不能同时有两条未结束的入住记录。
- `合同`：当前、到期、历史合同均可查找。续租生成新合同并保留旧合同，生效前不改变当前月租，生效时沿用人员、押金、旧欠款和预存。
- `更多`：产权方房租规则、统一房间费用、导入模板与导入工具。统一费用可仅用于新房间，也可明确勾选更新现有房间；已生成账单金额不变。

入住可以同时登记同住人和本次已收款。换房显示按天差价，可填写协商金额；负数表示应退。退租默认展示实收未退押金、欠款和预存，保存应退押金只生成待付，实际退款另行确认。

电脑保留表格，手机展示卡片和底部导航。核心表单返回原列表并保留筛选，浏览器启用脚本时也会恢复滚动位置。

房态卡片使用绿色空房、蓝色在住、橙色即将到期。未启用自动计费且尚未建账的合同显示“待登记”。按月收租可直接用于这类导入合同：应收按现有计费规则预填并允许修改，确认收款时仅创建选中月份的房租账单，不要求补齐押金，不启用自动计费或追补历史账单。押金、取暖费等仍在单独收款或全部账单中处理。

中介房态先预览再下载，在“中介房态 → 费用与挂牌价”配置水、电、物业、网费、取暖和停车展示标准，并批量维护每间房挂牌价和佣金基数。佣金基数同步房间资料，供后续签约使用，不改现有合同佣金。同一配置页可编辑联系人和联系电话，默认“张小姐 18518699513”，两项都留空时不展示。图片预览页可分别选择是否包含佣金基数、看房密码、联系方式；默认均包含，点击“更新图片”后，预览、下载、复制及分享统一使用所选内容。展示费用留空时沿用房间标准，不改实际计费；挂牌价同步房间资料，不改现有合同租金。挂牌价编辑卡片展示实时房态、朝向、楼层和面积。物业费、网费填写 0 在图片中显示“免费”；停车费分别配置月付和包年，预填 150 元/月与 1440 元/包年，包年留空则仅展示月付。图片用绿色标记空房、橙色标记即将到期，费用不同时逐房列出。“分享图片到微信”按钮始终显示，支持图片分享的手机可调用系统分享面板选择微信；不支持时点击按钮显示保存转发说明，手机也可长按图片保存。系统分享受浏览器、HTTPS 和设备支持限制。手机通过普通内网 HTTP 地址访问时浏览器限制直接分享，使用保存或长按图片方式；电脑用 localhost / 127.0.0.1 访问时支持复制图片的浏览器会显示“复制房态图片”，复制后到微信聊天框 Ctrl+V 粘贴。系统分享面板打开或返回成功不代表微信已接收，若微信提示共享失败，使用复制粘贴或保存发送。合同已过期但未退租的房间不自动作为空房发布。人员页“预览并下载报备”显示人数、最终文本和逐人修改入口。全部在住人员（包括暂住、管理员）与待报备退租人员一起导出。合同约定租期不足6个日历月时，主租客及该合同的常住同住人统一报备从合同开始日起1年（含首尾，如2026.6.1至2027.5.31），仅调整输出、保留备注，不改实际合同、个人原文或账务；暂住保留原说明。表格按样表的七列生成，退租人员的“合同时间”写“退租”。每次生成保存人员快照，可重复下载；发送后在本次报备页点击“确认本次报备已发送”，只移除该表中对应退租事件，后续退租不会漏报。下载不等于已发送，发送状态保存在数据库，跨浏览器有效。续租切换合同不算退租。上次导出变化提醒仍按当前浏览器记录。

旧 `import_current_state` 命令已停用，避免旧列索引和退租识别错误。网页导入只接受项目模板，不能直接按位置导入原悦山四表；原四表先用 `yueshan_check` 核对，再按身份增量同步。导入日期未知的暂住记录时保留空日期，不以今天或合同开始日补写。

### 更新现有安装

首页“生成报备表”进入报备预览，可直接调整最终报备文字，留空并保存恢复自动生成；人员资料和实际合同不随手动文字改变。退租人员可选择“报备 / 不报备”，点击“保存调整”或“保存并生成报备表”后保存到数据库，跨浏览器有效。选择不报备的人仍保留在预览中，可随时改回；不报备不代表已发送。已生成的历史表保持原快照。新的退租事件默认重新报备，不沿用旧事件的不报备选择或手动文字。

最新迁移为 `0013_billing_checkpoint`。使用项目 Python 环境，在启动前执行：

```powershell
conda run -n utils python manage.py migrate
```

若使用自己的 Python 环境，将命令中的解释器替换为对应路径。较早的迁移保留合同、账单、人员、收付款及抵扣记录，新增续租关联、自动抵扣开关和默认费用配置；旧支出的未分配金额不再自动抵扣新账单。

`0009` 增加独立报备开始日、允许入住日期未知，并防止同人重复在住。对先前增量导入的明确未退租且缺日期的暂住人员，依据已有来源备注补建入住关系；没有编造日期、押金或账务。已保存的主租个人报备起日补入新字段。若升级前已有重复在住，迁移会停止并要求核对，不会删除历史。

`0010` 新增退租报备状态及每次生成的人员快照。既有历史退租缺少已发送记录，升级后先全部列为待报备，补报并确认一次后不再重复；不推定历史资料已经发送，不改旧合同、入住和账务字段。

## 首版边界

- 当前使用 SQLite，适合本地电脑或家中内网服务器；数据库文件应放在本地磁盘。
- 少数管理人员、单实例、本地数据盘可继续使用 SQLite；频繁并发写入或多实例时再考虑 PostgreSQL。公网访问须配置 HTTPS、强密码、备份和访问控制。
- 身份证、电话属于敏感信息，不建议在未加权限和 HTTPS 的情况下公网暴露。
- OCR、身份证照片识别、合同照片识别后续可以作为“导入草稿”流程接入。
